$ design-review --target=hiago.sh@midfi-v1 23.may.2026 · 14 observações

Estudo do projeto e refinamentos sugeridos

O mid-fi v1 já tem identidade clara — tipografia de engenharia (IBM Plex + JetBrains Mono), paleta paper/ink quente, layout bento. O que segue são 14 ajustes pontuais para subir a fidelidade, reduzir ruído e dar ritmo à composição.

$ summary --by-priority

P0 · Antes de qualquer coisa

  • Sem hero real — falta uma frase-posicionamento dominante
  • Terminal está fazendo trabalho de hero, headline e bio ao mesmo tempo
  • Conteúdo do terminal soa AI-gerado (nomes de empresas reais, jargão clichê)
  • Hierarquia plana: 8 cards com peso visual idêntico

P1 · Refinamento

  • Excesso de prefixos $ ◇ ⌘ ● compete pela atenção
  • Tipografia secundária muito miúda (10.5–11px em mono)
  • Hover translateY(-3px) em todo card é cansativo
  • Status card mistura 2 listas heterogêneas sem separação clara
  • Microcopy "live every friday" / "shipping daily" / "deployed on a friday" são clichês

P2 · Polimento

  • Architecture diagram no card do GitHub é pequeno demais para informar
  • Sparkline definido em código mas nunca renderizado
  • Modal de vídeo tem 4 botões — provavelmente 2 bastam
  • Footer over-engineered (®, super-script, emoji bandeira)
  • Falta um único token de hierarquia — sem destaque cromático

01

Falta um hero real

P0

O usuário chega na página e o primeiro elemento de texto grande é a logo hiago.sh®. A frase de posicionamento — "Open to interesting problems." — está num card secundário, no canto esquerdo, do mesmo tamanho de um .h-card (19px). Não há um momento "isto é o que ele faz".

✗

O olho não encontra a tese

A composição bento entrega tudo de uma vez, sem ponto focal. Para portfolio sênior, isso custa caro: recrutador escaneia em 6 segundos e precisa identificar 1 frase.

recomendação Promover "Open to interesting problems" — ou uma headline real, tipo "Platform engineer. 13 yrs. Self-hosting everything." — para um bloco do tipo h-hero (44px+) acima do bento, ocupando largura total ou 9/12 da grid. Bento vira "below the fold".
02

Terminal está fazendo trabalho demais

P0

O terminal hero contém: identidade (whoami), histórico (git log), tópicos atuais (focus.md), e cursor animado. É bonito, mas o leitor precisa parsear ~9 linhas de texto monoespaçado pra extrair 3 fatos: quem ele é, no que trabalha, no que está focado agora.

✗

Densidade alta + fonte mono = atrito de leitura

Mono em 12.5px com line-height 1.65 e 6+ linhas vira "muro de código" antes mesmo do leitor decidir se quer ler.

hoje
$ whoami
hiago felipe · devops…
$ git log --oneline -n 3
a8c2f1e feat: n8n…
3d99e22 fix: gitops…
7b2e90c docs: mcp…
$ cat focus.md
n8n · mcp · tool-calling…
proposta
$ whoami
hiago felipe
devops & platform · 13 yrs

$ focus
n8n · mcp · tool-calling · gitops_
recomendação Cortar o git log — ele tenta provar "estou ativo" mas é a parte mais densa e menos informativa. Manter apenas whoami + focus. O sinal de atividade pode vir do card de status (já existe).
03

Microcopy do terminal soa fabricado

P0

Linhas como feat: n8n pipeline for nubank ops ou fix: gitops drift on k8s prod citam empresas/produtos reais sem contexto verificável. Para um portfolio público, isso pode: (a) gerar problemas de NDA, (b) soar como nome-dropping, (c) ser identificado como AI-gerado.

✗

Commits fake quebram a credibilidade que o portfolio quer construir

Se o git log for real, idealmente puxe de uma API de fato (GitHub events). Se for ilustrativo, troque por algo claramente genérico ou anônimo.

recomendação Duas opções: (1) Plugar fetch("https://api.github.com/users/hiago/events") e mostrar 3 eventos reais. (2) Trocar por nomes neutros: feat: n8n trigger refactor · fix: drift on prod cluster · docs: mcp guide v2.
04

Hierarquia plana — 8 cards com mesmo peso

P0

Terminal, status, contato, vídeo, repo, write-ups, newsletter, eventos — todos com a mesma borda 1px solid #0a0a0a, raio 10px, padding 16px. Para o olho, tudo é prioridade igual.

✗

Sem rítmo, sem tier

Boas composições bento variam densidade: 1–2 cards "alpha" (maiores, mais ar, tipografia maior), 3–4 "beta" (médios, conteúdo equilibrado), 2–3 "gamma" (pequenos, densos, suportam os alpha).

recomendação Definir 3 tiers visuais. Sugestão concreta:
  • α (alpha) — Hero + Video. Sem borda, fundo paper-2 ou dark, padding 28px, tipografia +1 escala.
  • β (beta) — Write-ups + Featured repo. Borda 1px, padding 18px (atual).
  • γ (gamma) — Status, Events, Newsletter. Sem borda, fundo paper-2, padding 14px, conteúdo denso em mono.
05

Inflação de prefixos e símbolos

P1

Conto: $ video, $ stack, $ subscribe, $ contact, ◇ next events, ◇ github, ⌘ latest write-ups, ● status, ▶ youtube, ◇ shorts. Cinco símbolos diferentes ($ ◇ ⌘ ● ▶), aplicados sem regra clara.

✗

Símbolo sem sistema é decoração

recomendação Escolher um símbolo por categoria semântica. Ex.: $ só para ações/comandos invocáveis ($ contact, $ subscribe). ◇ só para metadados/labels (◇ status, ◇ next events, ◇ latest write-ups). Eliminar ⌘ ● ▶ dos labels.
06

Escala tipográfica comprimida

P1

Os tamanhos atuais: 44, 19, 16, 14.5, 13.5, 12.5, 12, 11.5, 11, 10.5, 10, 9.5. Doze degraus, muitos deles separados por meio-ponto. O olho não distingue 10.5 de 11, mas o sistema fica frágil de manter.

✗

Type scale precisa de menos passos

recomendação Reduzir para 6 passos com razão clara (~1.25): 44 · 24 · 18 · 14 · 12 · 10. Mono 12 para meta/labels, mono 10 só para captions de imagem. Body sans 14 universal.
07

Hover translateY em todo card

P1

.card:hover { transform: translateY(-3px); box-shadow: 0 10px 0 -3px ... } aplicado em todos os cards, inclusive aqueles que não são clicáveis (status, newsletter form).

✗

Affordance falsa

Card que levanta no hover sugere "clique aqui". Quando metade dos cards não é clicável, vira ruído tátil.

recomendação Aplicar lift só em containers genuinamente clicáveis (write-up rows, video tiles, featured repo). Status e newsletter ficam estáticos — o hover relevante deles é no botão/link interno.
08

Status card mistura dois conceitos

P1

O card "status" tem: (a) flags de disponibilidade ("open · remote", "shipping daily", "live every friday") e (b) lista de eventos futuros ("nov '26 Web Summit"). São duas listas distintas separadas só por um border-top fino.

✗

Dois conceitos em um container

recomendação Separar em dois γ-cards (gamma): "status" e "speaking · 2026". Liberam espaço pra hero crescer, e cada um fica com função clara.
09

Microcopy escorrega em clichês

P1

"shipping daily" · "live every friday" · "self-hosted, deployed on a friday" · "no spam, just notes" · "open to interesting problems" — frases que aparecem em milhares de portfolios de devs/founders.

⚠

Não diferenciam, então não comunicam

recomendação Trocar por fatos específicos. "shipping daily" → "47 commits · 7d". "live every friday" → "next live: 28.may · 20h BRT". "no spam, just notes" → "1 email · primeira sexta do mês". Tudo verificável vira credibilidade.
10

Diagrama do repo é pequeno demais

P2

O <ArchDiagram /> tem 240×60 e mostra 5 caixas com texto de 8px. Em viewport real, é ilegível — funciona como textura, não como informação.

⚠

Decorativo demais ou pequeno demais — escolher um

recomendação Duas opções: (a) Aumentar pro card inteiro, virar a feature visual do repo card (label "open repo →" embaixo). (b) Substituir por screenshot de UI real do n8n workflow — mais reconhecível do que um diagrama abstrato.
11

Sparkline definido mas nunca usado

P2

Sparkline2 está declarado em midfi-v1.jsx mas não é renderizado em lugar nenhum. Código morto.

⚠

Remover ou aproveitar

recomendação Cabe perfeitamente no card de Newsletter mostrando crescimento de assinantes — ou no card de repo mostrando stars over time. Já está pronto. Se não for usar nas próximas iterações, deletar.
12

Modal de vídeo: 4 botões é muito

P2

watch full · save · share · transcript — quatro ações para uma única decisão (assistir). "Save" sem login? "Transcript" abre o quê?

⚠

Reduzir à ação primária

recomendação Manter apenas watch on youtube ↗ como primary e copy link como secondary. Save/transcript só fazem sentido se a feature existe de verdade.
13

Footer overdesigned

P2

© 2026 hiago.sh® · self-hosted, deployed on a friday · 🇧🇷 SP · UTC−3 · hey@hiago.sh. Tem ®, super-script, emoji de bandeira, copy clichê e duas formas de contato (footer + topbar social).

⚠

Diminuir, tirar o ®, tirar a piada

recomendação hiago.sh · são paulo · hey@hiago.sh · 2026. Quatro itens, sem floreio. ® num site pessoal soa irônico mas custa charme.
14

Falta um token cromático de destaque

P2

A paleta é paper/ink/red(live)/green(terminal). Tudo P&B exceto a bolinha vermelha "live" e o verde do $ prompt. Não há um accent consistente que ancore a marca.

✓

Definir 1 cor de marca

Pode ser o próprio verde do terminal (#6dd49a) ou um ink azul-noite frio. Aparece em: hover de link primary, underline em palavras-chave, pill de "open to work".

recomendação Eleger uma cor. Usar com parcimônia (no máx. 3 ocorrências por viewport). Documentar como --brand no design token, separado de --live (semântico) e --green (terminal).
